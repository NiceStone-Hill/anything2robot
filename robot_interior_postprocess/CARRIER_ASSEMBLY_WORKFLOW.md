# 独立载板参与布局的装配设计流程

实现与核查：2026-10-28（北京时间）。这是新的可执行后处理入口，替代“先固定电子布局，再补支撑”的默认设计思路。原 `run.py`、原 EPS 适配器、分壳命令和上游项目代码保留，便于对照。

**当前版本交付装配设计候选和逐项证据，不交付完整机器人已可制造/已可装配的保证。** 电子载板的几何、局部直线操作和静态布线可以验证；外壳紧固几何现已加入，详见 [外壳紧固说明](SHELL_FASTENING.md)。电机真实接口、电池/开关固定、紧固件实际配合、结构能力与实物试装仍必须补齐。`complete_assemblable` 不会因线路全部布通或载板全部生成而变成 true。

## 入口与输入

从 anything2robot 仓库根目录运行：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .conda-env/voxel_tool/bin/python -u \
  robot_interior_postprocess/assemble_robot.py \
  --config robot_interior_postprocess/configs/cactus_carrier_assembly.json \
  --output robot_interior_postprocess/outputs/my_carrier_run
```

输出必须是新的空目录。此命令直接读取 `cactus.json` 指定的 `robot_result.pkl`、制造 STL 与打印变换 CSV，恢复真实装配坐标，重新生成中空壳体；不读取旧 `placement.json`、旧电子支撑或旧线路。只对可信的本地 anything2robot pickle 使用既有导入器。

首次生成之后，可用 `--geometry-cache /path/to/new_run` 只复用基础中空几何。缓存需要原始输入/几何参数签名一致，且 `geometry_cache_manifest.json` 中每个壳体、空间掩码及空间报告的哈希均匹配。历史目录没有此完整性清单时，必须先重新生成一次。缓存不包含布局或布线结果。

### 泛用边界

- 面向刚体树、舵机驱动的动物形/人形机器人；固定舵机位置与关节，不进行舵机匹配。
- 布局内核使用显式实例 ID、所属刚体、几何与接口，不判断 `BATTERY`、`U1`、`base` 等名称。允许不同刚体各自包含多个电子载板；当前不自动把同一元件迁移到另一刚体。
- 首版开口是给定候选中的坐标轴平面双片切割；载板与开口平行，面向开口，合法姿态为枚举的面内 90° 旋转。斜装、曲面分割、滑轨和复杂旋转装入暂未实现。
- `legacy_eagle` 是已有仙人掌电路/供电替换适配器，不能直接宣称支持任意 Eagle 电路。其他机器人使用规范化机械输入和 `normalized` 电气输入，或编写独立适配器。
- 外部数据检索未接入运行。当前使用固定本地官方孔位记录与明确标注的概念包络；不把图像识别、原理图符号名或相似型号当成实物孔位证据。

## 已实现的八个阶段

1. **机械导入与基础空腔**：沿用可靠的装配变换和挖空器，固定电机；记录输入 SHA256。每个 link 都必须有开口候选，包含没有电子元件的肢体。
2. **安装档案与独立载板**：真实 PCB 使用本地安装目录中的孔、禁入区及明确紧固参数；元件先在壳外装到载板。未知固定方式使用概念托盘并记录 `component_retention`，不生成假孔。载板独立于壳体，预留外侧安装耳和两颗壳体连接螺钉。
3. **装配架构候选**：逐 link 枚举开口方向、切割偏移和承载半壳；默认配置候选，或使用同一 VLM 排序。没有按“最高元件”生成切割高度。
4. **受限布局 schema**：载板入口使用独立、严格校验的 carrier schema，定义所属内腔世界坐标 AABB 中的归一化中心范围、给定开口法向子集、配置中的面内旋转子集、间隙以及有界软偏好。初始候选、每次 EPS 移动、备用种子和最终选择消费同一份约束；禁止改元件归属或固定电机。模型不能降低本地几何间隙下限。失败时停止，不静默放宽约束。此 schema 的载板安装法向不同于旧入口的电气接口法向，不能直接互换旧 JSON。
5. **载板 EPS**：以整个“硬件＋载板＋紧固件”为单元，使用有上限的初始束搜索和扩展模式搜索进行平移与原子旋转。元件、孔、端口、载板和操作方向共用一个刚体变换。粗筛将本体与薄载板分别保守包围，避免把安装耳上方的空白全部误判为占用。过程记录显示至多三份真实粗筛可行种子图，种子之间共享视角和尺度；它们尚未通过精确装配检查。
6. **精确连接与操作复核**：载板连接两个实体矩形支座，支座寻根后融合到指定壳片，盲孔在最终材料合并后扣除。载板本身保持独立，检查根部、所属刚体、邻近壳体/电机包络、螺丝和工具。粗筛的不同种子可以回退到精确验证，而非只检验一个布局。
7. **布线与最终几何**：新支座预留为布线障碍；legacy 适配器重新构造电机接线通道并运行严格端口 A*。开通道可能改变壳体，所以重新生成连接并复核；最终线路圆管与壳片、载板、本体和紧固件再次做实体相交检查。有限重试目前调整概念电路的临时线尾方案，**尚未自动把布线失败反馈为下一轮电子布局移动**。
8. **装配与制造交付**：导出独立载板、融合支座的壳片、紧固清单、局部先后依赖和未验证事项。每个元件都有覆盖记录；需要但未解决的电机/盖板/固定接口不会被删掉以获得成功状态。

### 优化约束的实际含义

| 要求 | 当前处理 |
| --- | --- |
| 面向开口、平行安装 | 枚举的合法姿态保证；当前不搜索倾斜角 |
| 尽量共面 | 惩罚各载板安装基准面沿开口法向的深度跨度，不对齐不同厚度元件的中心 |
| 尽量无投影遮挡 | 惩罚投影重叠比例；空间不足时允许分层 |
| 元件/载板不可相交 | 粗分体占用硬筛，最终实体再验证 |
| 分层仍需能安装 | 插入、螺丝与工具共同形成依赖图；循环依赖拒绝 |
| 支座必须有根、孔不能被回填 | 精确布尔、寻根深度与材料连通检查 |
| 布线不能穿过最终材料 | 体素规划后再做线路圆管实体复核 |
| 重力与承载 | 必须显式给出参考重力；已知质量和局部重心可输出重力/支座力矩需求，未知质量、材料、紧固能力时保持 pending |

目标为共面、投影遮挡与投影紧凑程度，加上 schema 中 0–5 权重的软偏好：沿显式重力的高/低位置偏好，以及同一 link 元件间的靠近、共面和低投影遮挡。它们不是整机质心或结构强度证明，也**不是原 EPS 的增量真实线长联合目标**。线路在精确支座确定后单独计算。原线长/拥塞 EPS 保留为旧工作流对照，不能将新入口的目标误写为已优化真实线路长度。

## 装配顺序的语义

1. 无载板时，安装固定支座中的嵌件。
2. 在工作台上将有真实安装接口的 PCB 固定到独立载板；PCB 孔位和工具仅在此阶段操作。无固定资料的托盘仍是待设计任务。
3. 按载板依赖图装入并固定载板。后装载板允许挡住前一载板的工具方向，但前者必须先完成紧固；维护时逆序拆出。
4. 所有载板机械紧固完成后接线。连接器插拔和线束实际步骤还需要真实接口资料。
5. 合盖和外部紧固。为全部 link 生成外壳通孔、头座、连接柱、盲孔、环形定位与止挡，验证局部工具/螺钉路径及定位退出；更新逐片连接覆盖。实物配合与紧固能力仍为 pending。

直线扫掠是连续几何检查，不是离散抬升取样。螺钉的头和杆分别扫掠，避免把多颗螺钉之间的空隙或螺钉肩部错误填实。工具当前是指定半径的直杆空间，未包含完整手柄、扳手转角或人体手部。所有装配检查还缺少临时夹具和中间状态承载证明。

## VLM

两个模型环节分别记录来源：开口排序写 `model_provenance.json`；EPS 前的 restrict schema 写 `schema_provenance.json`。当前仙人掌配置 `layout_constraints.mode="llm"`，直接运行会真实生成载板 schema，读取相同 `.env` 与 `FunctionalAnnotationClient`。其他配置省略该字段时明确使用本地规则，过程标记 `ALG`。

增加 `--vlm` 使用 `robot_interior_postprocess/.env` 中原 restricted-schema 阶段的同一配置与客户端，获取整机/逐 link 观察图、载板尺寸、重力假设和待补数据，给几何生成的分割候选排序。它不填写孔位、质量、强度，不直接移动元件。`--proposal /path/to/proposal_raw.json` 明确回放模型排序；不得与 `--vlm` 同时使用，也不把回放称为新调用。

模型排序仍受原本地 schema 校验。首版只消费其中的坐标轴平面候选；其余策略保留为未支持，而不是近似执行。

schema 输入包含整机/逐 link 图、材料与禁入区切片、工作台载板图、显式重力与各实例的合法姿态。输出 `layout_constraints_raw.json`、编译后的 `layout_constraints.json`、上下文、提示词、逐次响应、`semantic_guardrails.json` 和 `semantic_final_validation.json`。规定中心是整个载板包络的中心，区域相对于所属 link 的可用内腔世界 AABB；这不代表 AABB 内的所有位置都可用，仍须通过空间掩码和精确验证。

`--layout-schema-proposal /path/to/layout_constraints_raw.json` 显式回放载板 schema。回放仍重新生成所有种子、EPS、支撑、线路和壳体紧固，不读取旧元件位姿。`run_generation_demo.sh --open` 默认回放已保存的真实开口排序和真实 schema；`run_generation_demo.sh --live-schema --open` 真实重跑 schema。概览区分 `VLM LIVE`、`VLM REPLAY` 与 `ALG`，并分别提供两个模型环节的跳转按钮。

## 泛用输入契约

配置以 `configs/cactus_carrier_assembly.json` 为例。数据层与实例配置分开：安装定义中的孔位处于局部 PCB 坐标；`world_from_interface` 由新布局原子生成，不继承旧布局配准位置。

非 anything2robot 导入器可以提供：

```json
{"mechanical": {"adapter": "normalized", "directory": "../my_robot"}}
```

目录中包含：

- `mechanical_scene.json`：`units="millimeter"`、唯一的 `parts` 列表，以及可选的 `motors`；电机条目沿用中心、轴向两端、半径和父子 link 契约。
- `meshes/<link>_hollow_assembly_mm.stl`：世界装配毫米坐标的有效闭合材料实体；已有空腔不能被填成实体。
- `space_masks.npz`：相同三维 shape 的 `usable`、`material`、`motor_block`、`protected_material`、`part_ids`；另含 `origin[3]`、正数 `pitch`。part_ids 从 1 对应 parts 顺序；内腔必须来自可信几何适配器。

外部适配器必须保证掩码与网格配准；最终精确检查不会仅凭掩码相信材料是空气。

规范化电气配置：

```json
{
  "electrical": {
    "adapter": "normalized",
    "file": "../circuit/connectivity.json",
    "wire_radius_mm": 1,
    "fixed_ports": []
  }
}
```

网络文件为 `schema_version=1, units="mm", nets=[{"id":"power","terminals":[{"instance_id":"board_A","port_id":"VIN"},{"instance_id":"pack_A","port_id":"OUT"}]}]`。每个载板配置的 `ports` 按端口 ID 保存局部 `position_mm`、单位 `normal` 和 `evidence`；固定端口提供实例/端口 ID、`world_position_mm`、证据。端点必须在有证据的布线空气中，不能自动跳到最近空气替代真实端口；需要线尾时由适配器明确提供。

当前 legacy 电路只有概念接口，因此独立记录临时线尾的选面和位置；布通不表示实际 MG4005V2 与模拟三线舵机电路兼容。

## 结果与验收

本次代码回归：107 项测试通过，其中新增载板/布线/重力/导出回归 18 项；Ruff 检查通过。`outputs/cactus_carrier_assembly_raw/` 从原始机械输出重新生成基础几何，`outputs/cactus_carrier_assembly/` 保存离线规则结果；最终主审查目录 `outputs/cactus_carrier_assembly_verified_live/` 是经用户批准向现有模型服务发送本轮上下文后得到的真实 VLM 结果，`model_provenance.json` 记录 `live_llm`、`gpt-6-sol`。最后一组结果为 4 个可拆载板、8 片含固定支座的外壳、14 条已布通线路；四个载板的局部操作和最终线材实体干涉检查通过。打印件逐个执行 STL 导出回读；仅去除零面积/重复三角形，不填补真实缺口，拒绝体积改变或非闭合结果。仍有 31 条完整装配/物理验收待补记录，状态为 `partial`。21 个装配任务包含明确的 pending 步骤，不能当作全部任务已经完成。

| 输出 | 内容 |
| --- | --- |
| `manifest.json` | 总体状态、源文件完整性、载板/壳片数量、路由和模型来源 |
| `carrier_placement.json` | 新位姿、开口平面、参考重力 |
| `hardware_dossiers.json` | 每个元件资料、载板参数与缺失项 |
| `support_ownership.json` | 载板、两端支座、承载壳片、根部和文件映射 |
| `assembly_sequence.json` | 阶段与依赖；pending 任务不伪装成已完成 |
| `assembly_validation.json` | 精确操作检查、最终线材干涉和制造阻挡项 |
| `load_report.json` | 已知重力需求或质量/能力缺失原因 |
| `candidate_evaluations.json` | 有限搜索、失败、EPS 改善和回退证据 |
| `routing_attempts.json` / `routing_summary.json` | 有限布线重试、选中的电气子目录和结果 |
| `meshes/*_piece_*.stl` | 含固定支座的壳片 |
| `meshes/*_carrier.stl` | 需要单独打印的可拆载板；不能与固定支座混淆 |
| `fasteners_bom.csv` | 需要选定规格/校准的原型紧固件清单 |
| `manufacturing_manifest.json` | 12 个候选打印件及角色；明确固定支座已在壳片中，不重复打印 |
| `shell_connections.json` / `shell_fastener_map.png` | 每个 link 的外壳连接、逐片覆盖与孔位图 |
| `index.html` / `preview.png` / `carrier_detail.png` | 离线交互预览、整机图和内部载板图 |

退出码 2 表示已输出候选但完整装配仍有阻挡；异常退出表示输入、搜索或计算失败。现阶段不提供无条件的成功制造退出码。不能通过填写一个“已验证”字符串跳过真实校验器。

仙人掌只能作为一种曲面壳体例子。新增测试包含不同命名的规范化机械场景、内部材料而非仅角点检查、薄载板与本体分开占用、真实孔位、原子旋转、邻近刚体挡住装入路径、寻根不足、投影偏好及缺失数据阻止完整验收。泛化范围仍需不同机器人、安装方式及实物试装覆盖。

## 下一批需要补齐的能力

1. 固定实物版本、质量/重心、连接器、紧固件及材料配置，补齐电池压条与开关面板接口。
2. 已生成外壳定位/紧固模板的实物配合与强度标定；真实电机两侧安装、零位和工具任务仍待实现，不能用电机包络重叠直接判断实际干涉。
3. 将精确布线失败反馈给下一轮载板位姿/架构搜索，并复用增量路由成本；目前有限重试只覆盖显式概念线尾。
4. 支座强度、螺钉/嵌件承载、制造方向、工作姿态下整机质量和接触/关节负载。
5. 夹具与全机装配中间状态、运动线束、维护与校准，以及孔位试片和实物装配。

这些不是当前已经通过的项目。它们也是实现“完整可装配机器人方案”所需的验收门槛；本版本建立了可追踪的输入、搜索、生成和失败出口。
