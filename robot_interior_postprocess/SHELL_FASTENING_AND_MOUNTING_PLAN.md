核查日期：2026-10-27。本文作为 `ASSEMBLY_PLAN.md` 的专项补充，优先覆盖当前分壳与支撑模块；已实现范围见下一段，其余章节保留开发目标与验收要求。

实施更新：支撑部分已增加显式安装接口、对孔螺柱、带筋承托板、可拆载板，以及螺钉/嵌件孔、局部工具和装入检查；已接入联合搜索和导出，使用说明见 `shell_partition/README.md` 文末。Uno 现已使用官方 Rev3e 的三个可访问安装孔，在仙人掌外壳中生成可拆载板和安装座；H3 因相邻引脚/封装冲突排除。封装 XY 来自官方 Eagle，高度与引脚伸出量仍为保守规划假设。新增避线槽保护孔位承托区和根部，载板阶段通过依赖图排序。相关回归共 62 项通过，包含保存的仙人掌布局四个电子目标联合生成、孔位、走线避让与无循环装配顺序。接缝连接、真实制造配合、结构和整机装配验收仍按下述规划推进。

最新支撑修正：`outputs/cactus_all_supports_v1/` 同时生成电池开口托盘、Pololu 双孔可拆载板、Uno 三孔可拆载板和开关承托。开口托盘取消装入方向的端壁，并仅在新增材料上切避线槽；载板允许向 PCB 四侧延伸寻找壳体固定点。永久根部始终参与所有装入检查；工具与可拆载板按明确装配阶段检查，并将其他硬件造成的遮挡转为依赖，拒绝循环。嵌件先于硬件与布线安装。最终实体和螺钉仍检查全部硬件及线路。电池/开关防脱、实际配准、强度、电机接口与壳体连接仍待验证。

## 1. 当前实现与缺口

- `shell_partition/geometry.py` 生成平面双片分割及包络装入/开盖检查，没有定位、紧固件与螺丝刀路径。
- `shell_partition/supports.py:support_options()` 已尝试包络六个面，生成承托板或托盘，并要求四根支柱连接所属壳片；不是只支持侧面。但接触面来自定向包围盒，板大小和支柱位置来自比例，没有真实安装孔或可靠的元件固定。
- `shell_partition/joint.py:evaluate_joint()` 联合搜索分割和支撑，已有线路保护、归属与连通检查，可作为扩展入口。
- `cad_models.py:fitted_rotation()` 根据外形尺寸选择配准轴，仅供预览。不能将该启发式配准直接用于制造孔位。
- 已检查 `outputs/cactus_joint_supports_review/`：四个电子目标均有概念支撑，固定与强度仍为 pending；整体 `partition_report.json` 为 partial，电机接口及接缝连接未验证。

目标：每个候选同时回答“两半如何定位并锁紧、元件如何固定、工具从哪里进入、如何装入和拆出”。

## 2. 外壳连接的首版结构

优先实现“内侧螺柱/连接耳 + 螺钉 + 热熔嵌件或捕获螺母”，配合可沿开盖方向退出的短定位销或局部台阶。先支持局部定位结构，再扩展连续唇边。

典型连接：螺钉从可访问壳片的外侧进入，通过螺钉头座和间隙孔，拧入另一片内侧螺柱中的嵌件；螺柱用筋连接壳壁。螺柱和嵌件在内部，螺钉头可以收进外表面的圆柱沉孔，但必须保留工具入口。完全隐藏的螺钉需要单独的可拆检修盖和无循环的拆装顺序，首版不默认采用。

| 特征 | 生成与验收要求 |
| --- | --- |
| 定位销、定位孔或局部台阶 | 提供装配间隙、止挡和明确退出方向；不形成倒扣或过约束 |
| 壳片 A 的螺钉通孔 | 与选定螺钉、装配偏差和打印补偿匹配 |
| 壳片 A 的螺钉头座 | 记录头型、直径、深度和剩余壁厚；圆柱沉孔与锥形沉头孔分开建模 |
| 壳片 B 的螺柱 | 记录外径、高度、根部筋、嵌件孔及盲孔底厚；不能直接在薄壁上开孔 |
| 嵌件或捕获螺母 | 记录具体型号、安装方向、安装空间、防转与防脱结构 |
| 螺钉长度 | 按夹持厚度、有效啮合长度和孔底余量选择标准长度，检查顶底、穿出与硬件干涉 |
| 工具入口 | 验证螺钉送入、刀头/刀杆及旋拧所需空间，并检查整机邻件遮挡 |

尺寸原则：M3 可作为首轮外壳连接候选，M2/M2.5 作为空间受限候选；具体规格由可用空间与载荷确定。以 M3 通孔约 3.2–3.4 mm 作为可配置试片范围，不作为当前机器人已确认的制造尺寸。嵌件底孔不能由“M3”推断，需要具体嵌件型号、材料及工艺数据。螺柱外径、根部厚度和螺钉头座同样参数化，经过局部试片后冻结制造配置。[SPIROL 指南](https://www.spirol.com/assets/files/SPIROL-Inserts-for-Plastics-us.pdf)可参考孔、螺柱和配合件的设计关系；不能将注塑建议直接当成 FDM 实测结果。

连接点沿接缝候选区域生成，按局部壁厚、可连接材料、工具方向、硬件/线路/运动避让过滤，再选择分布分散、跨距适当的组合。不能固定“所有外壳四颗螺钉”；连接数和间距也参与候选搜索，强度单独验证。

**现有开盖证明必须更新：**当前要求所有融合支撑严格处在分割面的所属一侧，以此保证平移分离。定位销、台阶和唇边会跨过此平面；应增加显式的跨缝配合接口，检查最终实体退出扫掠与配合间隙。不能只放宽 `within_half()` 后继续沿用原证明。开盖检查时先移除已卸下螺钉，再检查定位结构脱开，嵌件保留在所属壳片。

## 3. 元件安装模板

安装面由真实元件接口决定，壳体根部由内腔几何决定。两者之间可以通过载板、悬臂、筋或托架连接，不要求元件某个侧面直接朝向最近壳壁。

| 元件 | 优先模板 | 关键约束 |
| --- | --- | --- |
| Uno 等有安装孔 PCB | 对孔螺柱；孔位螺柱加承托板 | 板底器件/焊点净空、孔周围接触区、螺钉头与排针避让 |
| 小型降压板 | 对孔螺柱加局部载板 | 不压元器件，保留焊接、接线及散热空间 |
| 距壳壁较远的板 | 从壳壁伸出的承托板加加强筋，再按孔位固定 | 从 PCB 到载板、筋、壳壁的连续载荷路径；悬臂长度和变形风险 |
| 多块板集中安装 | 可拆电子载板，分别连接元件与壳体 | 两组紧固接口、整块载板的装入路径、实际可操作的装配顺序 |
| 电池盒 | 托盘、挡块及可拆压条/绑带 | 承托与防脱都要有，保留更换与出线空间；未知孔位不自动钻孔 |
| 滑动开关 | 依据实际型号选择面板夹持、独立支架或安装小板 | 滑块行程与外部可达；引脚和焊点不能作为机械夹持面 |
| 原机械电机 | 真实型号的固定侧、输出侧接口 | 保留独立数据缺失项，禁止用 SG90 等其他型号孔位替代 |

增加 `hole_standoffs`、`ribbed_shelf`、`removable_carrier`、`retained_tray` 等有限模板。支柱数量服从孔阵列与连接需求，取消必须四根寻根支柱的限制。支撑归属扩展为“元件 → 安装接口 → 载板/支撑 → 制造壳片 → 刚体”，记录每个可拆连接。

## 4. 如何获取可信安装信息

BoardRepo 用于发现公开硬件项目、源 PCB、BOM 和机械设计案例。其[开发文档](https://boardrepo.com/docs)说明公开板页可通过 HTTP 读取 Markdown；MCP 每次调用需要 OAuth token，工具列表应从连接后的服务发现。本轮查阅了公开网页，未连接 MCP，也未修改账户配置。

数据工作流：确认厂家/型号/硬件版本 → 查原厂机械图与 PCB/CAD → 必要时通过 BoardRepo/GitHub 寻找对应源文件 → 提取候选孔与接触面 → 核对语义和版本 → 注册为可复用的本地安装定义。相似板子只能作为参考，不能自动赋予当前元件制造孔位。

解析优先级：

1. 官方尺寸图、官方 PCB 源文件及实测数据互相核对。
2. KiCad/Eagle：解析板轮廓、板厚、安装孔/槽、封装位置与旋转、底面变换。必须区分安装孔、焊盘孔和过孔；不能把所有 NPTH 或所有大孔当成紧固孔。
3. STEP：圆柱面/孔轴可提供候选几何，但需核对通孔、螺纹与实际用途。STL 孔识别仅作辅助。
4. 图片或模型推断：保留待确认状态，不据此生成声称已确认的制造孔。

当前已有可用资料：

- [Arduino Uno R3 官方资源](https://docs.arduino.cc/hardware/uno-rev3/)提供 CAD 和机械资料，应从匹配版本提取完整孔阵列；不要默认四孔是规则矩形。
- [Pololu D24V50F5 官方页面](https://www.pololu.com/product/2851)明确有两个直径 0.086 英寸（约 2.184 mm）的孔，适用 M2/#2 螺钉；两孔横向、纵向间距分别为 0.53 和 0.63 英寸（13.462、16.002 mm）。这是已找到的数据，完整局部孔坐标和坐标原点仍需从图纸/DXF/STEP核对。
- [Adafruit 875 电池盒](https://www.adafruit.com/product/875)提供外形尺寸；当前未确认可直接使用的安装孔阵列。
- [Adafruit 805 开关](https://www.adafruit.com/product/805)有数据表入口；其与实际 BOM 的对应仍需确认，不预设有螺丝孔。

本地 `hardware_catalog/` 每个定义记录：型号和版本、来源 URL、文件哈希与许可、证据状态、毫米单位、局部坐标系、CAD 注册变换、板轮廓和板厚、孔中心/轴/直径/类型/有效深度、接触与禁压区、端口及工具空间。实例记录所属 link 和完整位姿。

孔位、板法向和端口共用同一变换链：`T_world_component × T_component_interface × p_interface`。显式处理原始 CAD 原点、旋转、PCB 底面镜像及单位，不按包围盒缩放孔距。未经审核的预览配准不能提升为制造配准。

## 5. 联合搜索和装配验证

候选从当前“分割面 × 打开方向 × 支撑”扩展为“分割面 × 定位/紧固布局 × 元件安装模板 × 根部位置 × 装配顺序”。先粗筛空间，再精确生成有限候选，最后验证最终实体，避免组合爆炸。

硬约束包括：安装孔同轴、零件连通及最小材料余量、允许接触、螺钉长度、线路和连接器避让、工具可达、元件及载板装入、盖板与定位结构退出、所属刚体及运动避让。通过硬约束后再比较紧固件数量、材料、悬臂长度和维护便利性。LLM 可排序模板与布局，孔位和几何由已核实数据与程序决定。

碰撞模型需区分材料实体、孔/空腔、允许接触、配合接口和阶段性工具空间。现有凸包包络会填满安装孔，不能直接用于螺柱与孔的最终配合验证；保留包络用于粗筛，精检用真实板体及接口几何。

装配任务记录先后依赖：安装嵌件 → 将板件固定到载板 → 安装载板 → 接插线束 → 合盖定位 → 从外部拧紧壳体螺钉。实际顺序由工具与入口约束选择，并验证反向拆卸；不能生成“先封壳才能拧紧、拆壳又先要拧开该螺钉”的循环。工具按当时已安装对象检查，首版可用少量明确顺序模板。

首轮保持已有硬件位姿和线路作为约束。失败时输出需更换分割、支撑或需重排布局的原因；后续通过明确入口将失败区域反馈布局/布线，不静默移动已有元件。

## 6. 代码落点与交付顺序

继续保持独立后处理入口，不要求立即改动原布局/EPS。

| 阶段 | 代码与交付 | 验收 |
| --- | --- | --- |
| A：安装数据 | 新增 `hardware.py`、`hardware_catalog/`；先接 Uno 和 Pololu；导出 `hardware_interfaces.json` | 型号、孔阵列、坐标变换与来源可追溯；缺失项显式保留；旋转后孔与模型一致 |
| B：壳体连接最小样件 | 新增 `shell_partition/fasteners.py`；生成连接耳/螺柱、嵌件孔、通孔及头座；输出参数和紧固件 BOM | 简单双片腔体能装入嵌件、合盖、拧紧并拆开；工具不受遮挡，螺钉不顶底 |
| C：真实部件支撑 | 扩展 `supports.py` 为对孔螺柱、带筋承托板和可拆载板 | Uno/Pololu 按真实孔固定；板底无压碰，根部连通，载板可装入与拆卸 |
| D：联合候选 | 扩展 `joint.py`、`geometry.py`，新增阶段任务检查；更新提示词与 schema | 连接结构和支撑进入候选选择；跨缝定位采用真实退出检查；失败不省略必需连接 |
| E：当前机器人复核 | 更新 `io.py`、`viewer.py`、报告；新目录保存结果 | 展示螺钉、嵌件、孔轴、工具和归属；提供完整拆装任务，旧 partial 不自动升级 |

测试覆盖具体失败：孔位旋转/底面处理错误、孔被后续融合回填、螺钉过长或啮合不足、嵌件无法安装、薄壁穿孔、孤立螺柱、定位倒扣、工具被邻件挡住、载板终态能容纳但装不进去、装配依赖循环、承托板堵线路。尺寸和几何先用局部试片验证，再扩展整机。

新增输出建议：`hardware_interfaces.json`、`shell_connections.json`、`mounting_plan.json`、`fasteners_bom.csv`、`assembly_sequence.json`、`assembly_validation.json` 及独立最终零件。每条连接记录两端零件、坐标、紧固件/嵌件规格、孔径和孔深、安装方向、工具及证据。

推荐首个完整交付：一个双片测试腔体，具备内部连接螺柱、外侧可操作螺钉、局部定位，以及一块按照真实安装孔固定的 PCB 承托板。先在这个单元完成数据、配合和拆装闭环，再应用于仙人掌曲面腔体。电机真实接口、结构强度与实物验证维持独立状态。
