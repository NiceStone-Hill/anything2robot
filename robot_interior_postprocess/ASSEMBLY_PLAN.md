# 从内部布局到可装配机器人：后续开发方案

2026-10-28 更新：当前主开发方向已调整为“独立载板参与 EPS → 固定支座与分壳 → 重新布线 → 分阶段装配验证”，已增加独立可执行入口。以 [载板装配工作流](CARRIER_ASSEMBLY_WORKFLOW.md) 的实现/待完成清单为准。下文保留此前研究背景，不应将其中全部规划视为已实现。

核查日期：2026-10-21。本文为开发方案，尚未实现下述新增能力。

## 1. 当前状态与证据

当前工作流是：外部图像转三维工具取得 STL → 人工标注关节和轴线 → 电机参数优化与外形修改 → 制造连接结构 → 独立后处理挖空 → 固定电机条件下布局电子模块 → 布线、EPS 优化和预览。仓库入口以 STL 为起点，照片转三维不是当前入口内已实现的步骤。

本次检查了工作区代码、配置、既有方案和最新保存的运行结果；没有重新调用视觉模型或重跑完整生成流程。执行现有后处理回归测试：19 passed。

| 当前能力 | 依据 | 实际边界 |
| --- | --- | --- |
| 电机选型、连接结构 | `script/motor_param_lib.py`、制造后处理 | 电机库主要是高度、半径、扭矩，高度还加了 15 mm 连接余量；不能直接作为精确本体尺寸和孔位 |
| 电机装配位姿恢复 | `robot_interior_postprocess/mechanical.py` | 输出中心、轴线和圆柱预留包络；还没有真实型号安装坐标系和绕轴角 |
| 真实挖空及电机附近保材 | `robot_interior_postprocess/space.py` | `mount_support_mm` 扩大电机附近保护区，未生成电子板螺柱、螺钉或可拆盖 |
| 电子布局与路径优化 | `layout.py`、`optimization.py`、`routing.py` | 以概念包络和临时端口搜索；EPS 拒绝未同步更新接口的旋转 |
| 真实 CAD 预览 | `cad_models.py` | 用尺寸排列选择轴向配准；未据此重新验证真实孔位、端口和碰撞 |
| 视觉模型约束 | `semantic_bridge.py` | 可提出受限布局约束，但闭合内腔适配器当前拒绝外部操作空间与部分外置元件 |

最近保存结果 `robot_interior_postprocess/outputs/layout_test_20261015_191928_581453/`：4 个外壳部件、3 个固定电机、7 个已布局对象、14 条已布通分支，状态为 `concept_complete`。配置里的可移动模块是 Uno、电池、降压板和开关，尚无 IMU。该结果的成功范围是静态概念包络和路由验证。

另外两项直接影响实物：

- 电机连接模板缺失时，`ensure_motor_tenon_template()` 会按半径比例缩放其他型号模板。这可能同时缩放孔径和孔距，不能作为真实型号的安装依据。已有模板也需要逐一核验，不能仅因文件存在就认定正确。
- 当前电路将模拟三线舵机映射到原机械电机；原型号的供电、控制协议和连接器未确认。机械参考库记录本例为 MG4005V2，但后处理场景本身没有保存可信的型号 ID。更换成 SG90 等硬件需要重做电机性能与上游几何设计。

## 2. 目标与核心改变

下一阶段的目标是：给定确认型号的硬件，生成能按规定顺序装入、固定、接线和关闭的机械设计，并通过一套实物样件验证。

布局候选从“元件位姿”扩展为“元件位姿 + 安装模板 + 壳体连接位置 + 装入方向”。检查需要同时处理：

1. 元件本体、插头及实际接插空间。
2. 螺柱、托架、压条、螺钉、螺母或嵌件。
3. 支撑与所属壳体/载板之间连续的材料连接。
4. 元件和线束的装入路径、工具操作空间、盖板拆装路径。
5. 功能方向、所属刚体、运动扫掠区和载荷传递。

这些体积不能全部混为一种障碍：安装面允许指定接触，螺钉与对应孔允许装配关系；工具空间可在某些装配步骤与后来安装的零件重合。首版可采用保守的全程保留工具空间策略，并明确记录其限制。

## 3. 改进后的流程

```text
确认实物 BOM、型号版本和原厂/实测安装数据
  → 恢复机械场景，补全功能坐标系与电机完整位姿
  → 核对或重建电机安装接口，保护承力区
  → 生成基础中空壳体，提出检修开口/分壳候选
  → 联合生成元件位置、安装结构和装入方向候选
  → 硬约束筛选，再比较线长、结构用料、重心和维护便利性
  → 生成支撑、紧固孔、盖板及必要外部接口的精确几何
  → 从最终材料占用重建规划域，布线并生成线夹
  → 再次复核几何、装入顺序、工具可达性、运动及载荷
  → 导出制造文件、紧固件清单、装配步骤和传感器外参
  → 打印孔位试片/安装样件，实物校验后再打印完整外壳
```

保留“先形成真实内腔，再在许可空间布局”的现有原则。安装结构必须在候选筛选时估算，在确定后精确生成；不能等线长优化完再无约束地补支撑。如果最终结构或线夹堵住线路，回退该候选并重新布局/路由。迭代到预算仍不可行时报告具体原因，不能删去硬约束。

## 4. 统一硬件安装库

建议新增 `robot_interior_postprocess/hardware_catalog/`，将器件定义与机器人实例分开。器件定义按厂家、型号、版本记录；实例引用定义，另存所属部件、位姿和安装方案。

| 数据组 | 必需内容 |
| --- | --- |
| 身份和来源 | 型号、版本、数据来源、CAD/图纸校验值、原厂/实测/估算状态 |
| 本体几何 | 原始 CAD、碰撞模型、质量、重心、局部坐标原点和显式 CAD 配准变换 |
| 安装接口 | 各安装面的局部坐标、孔中心和轴向、通孔/螺纹孔、规格、有效深度、允许螺钉伸入量、接触与禁压区域 |
| 接口和空间 | 连接器坐标与方向、插头实体、插拔扫掠体、出线区、线径及弯曲要求 |
| 功能约束 | 允许朝向、角度容差、所属刚体、温度/振动等条件，区分硬要求和偏好 |
| 安装方案 | 螺柱/载板/托架/压条模板、紧固件与工具规格、装入方向和先后关系 |
| 制造配置 | 材料、打印方向、孔径补偿、嵌件规格与工艺试片结果 |

只靠 STEP/STL 不能可靠推断全部安装语义；第一版从图纸或实测人工标注。孔径、螺纹底孔和嵌件孔不能统一写成一个经验值，分别由器件图纸、紧固件和制造配置决定。未知值保留缺失状态，允许概念预览，但不得输出已验证的制造孔位。

## 5. 电机安装需要补哪些信息

电机中心和转轴不足以决定孔的位置。需要分别定义：定子固定面、输出端连接面、输出轴/定位止口、电气接口，以及确定绕轴角的方向基准。

- 在上游结果里持久化 `motor_model_id` 与型号版本，停止依赖尺寸反推型号。
- 把本体长度与 15 mm 连接余量拆开，分别保留真实本体、机械连接和规划包络。
- 根据真实双侧孔阵列、止口和螺纹规格生成接口；父连杆连接定子，子连杆连接输出端，检查载荷路径和可动间隙。
- 对历史模板建立型号和来源映射；制造模式遇到缺失数据时明确失败。概念模式可继续使用近似模板，但不能赋予制造验证状态。
- 保持现有关节轴线和位置作为第一轮约束；若真实硬件或支撑不适配，输出上游重设计请求，重新检查电机性能、外形和干涉。

首个电机交付应是一个真实型号的安装试件：固定侧与输出侧各一件，验证孔距、螺钉长度、工具操作和转动间隙。无需等整机外壳完成才发现接口不匹配。

## 6. IMU 的方向与安装语义

先选择具体 IMU 模块，按整块模块安装，不把板载芯片作为散件重新布局。

方向要求分两类：器件/算法明确限定的方向作为硬约束；允许通过软件变换的方向必须保存传感器到目标刚体的旋转和平移。不能给全部 IMU 统一套用“必须水平”。传感器坐标系与机体坐标系及其旋转关系见 [VectorNav 的坐标系说明](https://www.vectornav.com/resources/inertial-navigation-primer/math-fundamentals/math-refframes)。

实现内容：

- 在设计配置中明确机器人前、左、上及重力方向，并核对与现有装配坐标的关系；不从模型外观或文件轴名自动猜测。
- 对测量机身状态的 IMU，明确绑定目标机身刚体。仙人掌的 `BODY` 和 `base` 之间有运动关系，需先确定控制所称的“机身”是哪一个。
- 定义芯片轴到模块轴、模块轴到安装座、安装座到所属 link 的变换；导出 `imu_extrinsics.json` 和 URDF 固定变换。不要直接把全局装配坐标当成 link 局部坐标。
- 第一版使用少量预定义合法朝向。一次旋转同时更新本体、孔位、端口法向、功能轴和装入方向；补齐此能力后再扩展 EPS 旋转。
- 安装座采用方向标记和防装反结构；固定方式按具体模块和其供应商说明设计，并实测装配后偏置与振动表现。

机械约束也可能影响测量：Bosch 的 [BMI08x 设计说明](https://community.bosch-sensortec.com/knowledge-base-pg631enp/post/bmi08x-design-guide-ZWU1wwmHYnSw68r)指出装配造成的 PCB 弯曲可能改变偏置，并建议装入外壳后校准。这支持增加装配后校准步骤，但不能据此直接给未知 IMU 指定通用螺钉扭矩或减振参数。

## 7. 支撑、开口和装配路径的首版策略

第一版先做有限模板，避免同时求解任意结构形状：

| 对象 | 首版安装方案 | 重点检查 |
| --- | --- | --- |
| Uno/降压板 | 实测孔位的螺柱或可拆载板 | 板底净空、连接器、螺钉长度、支撑根部与壳体连接 |
| 电池盒 | 托盘、限位挡块、可拆压条或适用绑带 | 三方向约束、质量载荷、替换路径、接线应力释放 |
| IMU 模块 | 有方向基准的独立安装座 | 所属刚体、轴向、模块受力、外参和校准 |
| 电机 | 真实型号双侧安装座 | 双侧孔阵列、止口、载荷路径、工具和运动间隙 |
| 开关/USB | 明确面板开口或可拆盖访问 | 外部操作/插拔方向、固定结构和开口边缘余量 |

优先尝试一块可拆电子载板加明确的维修盖，但必须先检查电池/载板能否经过候选开口。对于现有曲面壳体，首版允许人工指定少量分壳面或盖板区域，由程序验证后选择；开口太小或切到承力区时换方案。

装入路径先支持沿指定方向的直线插入/拔出，对完整元件加插头计算扫掠碰撞。需要复杂旋转装入的布局首版标记为未支持，而不是因终态无碰撞就判定成功。螺丝刀与螺钉进入空间也要验证。

## 8. 代码落点与几何分辨率

| 模块 | 计划修改 |
| --- | --- |
| `script/motor_param_lib.py`、上游结果序列化 | 带型号 ID 的电机定义，拆分本体与连接余量，兼容旧优化器读取 |
| `mechanical.py` | 导入完整电机位姿、安装基准和型号，保留打印变换，补全 link 坐标及可信运动范围 |
| 新增 `hardware.py` | 硬件安装库校验、显式 CAD 配准、孔位/端口/功能轴统一变换 |
| 新增 `mounting.py` | 参数化螺柱、载板、托架、压条和电机接口，记录壳体连接关系 |
| 新增 `access.py` | 开口与盖板候选、元件及工具扫掠体、装配先后约束 |
| `layout.py`、`optimization.py` | 对“位姿 + 安装方案”搜索；加入支撑可连接、方向、可达性硬约束和失败解释 |
| `semantic_bridge.py` | 将硬件确定的约束作为不可覆盖输入；模型只建议可选区域/方案，不生成未经核实孔位 |
| `space.py`、`routing.py` | 区分基础壳体与安装后材料；按生成的支撑和线夹重新构造占用并布线 |
| `cad_models.py`、报告/URDF 导出 | 使用明确安装配准，展示螺钉/工具/装入路径，导出传感器外参与装配清单 |
| `common.py`、运行缓存 | 安装库、型号版本、几何、支撑、盖板、制造配置与算法版本全部进入相关缓存签名 |

现有 `pitch_mm=3` 可继续用于全局粗搜索，不能作为小螺孔和小壁厚的最终验收依据。安装接口采用参数化实体/CSG 精确建模；局部细化或网格用于碰撞复核，制造补偿单独记录。优先复用现有布尔工具，遇到加工接口表达不足时再补充 CAD 内核，不重写布局和路由器。

新增材料先与壳体合并，再按特征顺序扣孔和开口，避免合并后回填孔。分壳及盖板分别导出；所有验证以最终零件为准。

## 9. 分阶段交付与验收

| 阶段 | 具体交付 | 完成条件 |
| --- | --- | --- |
| A：硬件数据闭环 | 一个确认电机、现有电子模块与新增 IMU 的型号/接口记录；真实电路映射；孔位试件 | 缺失项可追溯，制造数据不来自猜测或比例缩放；真实电机控制和供电方案明确 |
| B：最小可装配单元 | 一个腔体、可拆盖、控制板螺柱、电池托盘、带方向基准的 IMU 座 | 实物可装入、固定、接插、关闭、拆出；孔位与方向经过样件验证 |
| C：接入自动布局 | 候选安装模板、装入/工具约束、支撑后重布线、失败原因 | 无支撑连接的候选被拒绝；支撑堵线触发回退；旋转后所有安装与接口数据一致 |
| D：整机验证 | 三个电机接口、全部电子与线束、最终质量/重心/惯量及装配步骤 | 在声明运动范围内完成规定检查，载荷变化回传上游；最终实物样机完成装配测试 |

不建议先追求任意元件/任意外壳的全自动装配规划。先用仙人掌的一处腔体验证数据和机械模板，后续再扩展多舱分配、复杂装入路径和连续运动线束。

每阶段新增测试应覆盖实际失败模式：旋转后孔和端口错位、孤立螺柱、支撑根部未连壳、螺钉过长、终态可容纳但装不进去、工具被挡、盖板碰撞、IMU 方向/所属 link 错误、安装结构堵住原线路，以及数据修改导致缓存失效。

保留 `concept_complete`，另按几何、装配路径、结构、电气、运动、实物验证分别记录 `passed/failed/pending` 及证据。几何检查通过不能自动提升为实物已验证，后处理改造也不能沿用旧机械分析的成功状态。

建议最终新增输出：`hardware_manifest.json`、`mounting_plan.json`、`fasteners_bom.csv`、`assembly_sequence.json`、`imu_extrinsics.json`、`assembly_validation.json`、参数化安装源文件和独立最终打印零件。已有布局与路径输出继续保留。

## 10. 推荐立即开始的工作包

1. 建立硬件安装 schema，迁移当前四个电子模块；新增具体 IMU 的记录，缺失数据显式列出。
2. 追溯本例电机型号和版本，获取双侧安装图及真实接口；生成单电机安装试件，替换未经核实的缩放模板路径。
3. 确定目标机身刚体与功能方向，补全硬件、孔位、端口和功能轴共用的变换链。
4. 对一处腔体实现人工指定开口 + 参数化载板/支撑 + 直线装入和工具验证，先交付可打印样件。
5. 样件验证后，将这套安装模板和可达性约束接入现有候选生成、EPS 和布线路径。

当前可直接推进 schema、模板接口和验证器开发。真实孔位制造、电机电路映射和 IMU 最终方向需由确认型号的数据与控制要求确定；缺失时继续做框架和概念验证，不填造数值。
