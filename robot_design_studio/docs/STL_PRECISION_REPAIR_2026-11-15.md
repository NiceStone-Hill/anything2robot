# 0.7.6 STL 精度问题的有预算自动修复

本轮用户要求适度放宽探索阶段的拒绝。实际截图对应 `project_c26f179510c941d9`（短编号 c941d9），500 mm 原 Tripo 外观、单颈关节 MG4005V2，身体和尾部固定。原失败运行 `run_6f65cadbcab04118` 的其他结构检查通过，只有身体 STL 导出及被该失败候选连带影响的实体检查未通过。

## 诊断

捕获最终身体外壳的原始内存网格，水密、有向、正体积均成立，体积 1306202.419660434 mm³。STL 用 float32 存三角形顶点，4 个不同拓扑顶点出现位置别名，重新加载合并后形成一个四面共边的非流形边。体积偏差约 0.001 mm³ 很小，实际拒绝原因是非水密，并非体积限额过严。ASCII STL 也不能解决其中精确重合的位置。

旧流程还无条件先重新导入几何引擎并简化，且后续检查曾使用失败的序列化候选，因此不能以预览外形完整作为有效导出证明。

## 修改

- 优先尝试原索引几何的 STL 导出，不再无条件简化。
- 如果内存实体有效且存在 float32 位置别名，仅对这些顶点沿各自表面法向向内微调，按固定有限列表尝试 0.00005 / 0.0001 / 0.00025 / 0.0005 mm。不移动其他顶点，不改原 STL，不缩放模型、电机或关节。
- 每次都重新导出、加载、焊接、去退化并再加载，要求水密、正体积；最终仍检查连通、装配、安装面、插入和关节运动。
- 所有输出顶点距原顶点集最大距离≤0.001 mm，体积变化仍≤max(0.001 mm³, 原体积×1e-6)。原体积预算不放宽。已有微小边简化仅作最后备选，也受同样预算约束。
- 记录方法、受影响顶点数、最大位移、体积变化及全部失败尝试；页面显示已记录网格修正，制造放行仍为 false。

这相当于让可自动修复的数值误差继续生成，不把非水密的 STL 直接标成通过。当前案例已修复，暂不需要启用“无效 STL 继续布局”的降级通路。
