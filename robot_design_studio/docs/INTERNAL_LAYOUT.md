# 内部电子装配 0.4

2026-11-15，Ubuntu；在现有系统中继续构建。用户最新优先级是尽快贯通主流程，N20 降成本替换后置。竖直分壳、电子板竖放是已记录的后续候选，本轮没有冒充实现。

## 正式入口

界面第 05 步，`POST /api/projects/{id}/layout`。输入当前版本、`mode: reference`、全部已选择的内部实体部件，每个实例登记：`instance_id`、`dimensions_m`、`owner_body_id`、`evidence: engineering_assumption`、`note`。支持 1–16 个控制器、传感器、电源或分线部件。不能静默遗漏没有包络的电源。电机已经属于机械装配，散线、接头、紧固件在后续线束/端口登记中处理。

Pico 2 的 55×25×12 mm 和 MPU6050 的 25×20×10 mm 是明确可编辑的**软件试算包络**，不是官方尺寸，也不是实验室实测。实物参数仍为 null。未知实物不阻止软件试算，不获得制造或上电放行。

## 实际计算

1. 读取本项目当前机械任务，逐一核对资产摘要及闭合实体。采用原始身体区域作为凹形容纳约束，不使用外观凸包。旧任务没有区域记录时需要重新生成一次结构，旧产物保留。
2. 按包络面积排序，在指定刚体内搜索 2 个平面朝向、上盖/底部 2 种安装面、3 档高度、7×7 平面格点。先尝试靠边安放以留出后续部件空间。电机和原外观不缩放。
3. 对整件包络及托盘检查域内包含、所有已有实体碰撞；支撑柱通过射线落到真实壳/盖表面，以实体交叠确认连接后再合并。托盘生成 M2 候选孔、绑带槽和边缘止挡，不虚构 PCB 安装孔。柱上的嵌件孔是工程假设，实际规格未核实。
4. 上盖安装的电子件随盖整体向 +Z 移出，然后在外部从盖内侧拆托盘。检查整体上盖的离散取出位置，覆盖初始 0、0.25、0.5、1、2、5 mm 和 13 个全程等分位置；**不是连续保证**。PCB 托盘移出及工具空间使用连续保守包围盒/工具柱；求解多托盘先后顺序，不让它们穿过彼此。
5. 新固定柱、托盘与电子包络加入整个装配，再检查静态碰撞与原关节采样动作。每件 STL 导出后重载，检查水密、正体积及打印件连通性。

结果保存 `component_placements`（实例/归属/米制变换/尺寸来源）、`layout_assets` 和 `layout_result`。只有全部登记检查通过才写入当前装配归属。失败候选、输入和中间产物保存在运行历史中。

## 数据与导出

不覆盖 `mechanical_result` 或原机械资产；内部装配是明确依赖机械运行的新派生装配。独立包 `layout-review.zip` 含修改后的完整装配和所有新实体。项目审阅 ZIP 中 `internal-assembly/` 是含电子的完整版本，`mechanics/` 是原机械版本，不可混用其壳体。摘要不符、版本不符、机械来源改变时拒绝导出。

改变部件选择或源模型会使内部布局失效并清除派生归属。仅配置几何包络时，不改变逻辑网络；以新项目版本独立重校核电路副本，保留原电路任务，不声称再次调用 AI。

本轮没有登记物理接头位置、插拔工具通道、绑带与元件真实接触、材料/嵌件/螺钉配合、散热、质量载荷和线束。实际电子布局的工程候选已实现；“完整机器人可制造”仍未完成。
